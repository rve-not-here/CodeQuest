# Resources Css

## Console chrome is gone; guest surfaces are cover sheets
The admin console block (`.atlas-admin`, `admin-management`, `admin-*` tables/forms/toolbars, `.console-sidebar*`, `.panel-pagination`, `.admin-crumbs`/`.admin-row-link*`/`.admin-beat-*`) and the `body.console-ui` block have been deleted from app.css — do not reintroduce them. Every authenticated surface (student, teacher, admin, operator) is an `.atlas-records` sheet. Public pages (`welcome`, `auth/login`) compose `.atlas-cover` (column flex, `min-height: 100vh`, so the foot rule sits at the viewport bottom) + `.atlas-cover-head` (brand, `.atlas-cover-tools` with the shared `<x-theme-toggle />` and the `System 404` stamp; the stamp hides below 480px so the head stays one row) + `.atlas-cover-body` (2-track lead/register grid, 1 track below 900px) + `.atlas-cover-foot`. The access register adds `.atlas-access-alert` / `.atlas-access-form` / `.atlas-access-field` / `.atlas-access-notes`. Filter labels are not a class: `.atlas-index-filter > label` is styled directly (11.5px sentence case since the 2026-10-22 readability pass), so plain `<label>` inside a filter grid is correct. Error pages are the exception: `errors/layout.blade.php` is inline, asset-free CSS (see its own note) and never loads the Vite manifest.

## Structure and utilities (Engineer's Log)
Tailwind v4 CSS-first: no tailwind.config.*; the system lives in `@theme` in resources/css/app.css and the tokens are the real colour authority in both themes — never hard-code palette hexes in blades. Light and dark are one palette under two lights; dark mode is a class strategy on `<html>` with a no-flash inline script, light default and a two-option control that SETS the mode (Light | Dark, the option in force is pressed). Fonts load through the laravel-vite-plugin `bunny()` helper (resources/js/app.js / app.css), never a hand-written hosted stylesheet. After editing app.css, re-run `npm run build` or the served manifest CSS won't change; run `npm run build` before declaring a visual change complete.

## .table-stack responsive utility lives in @layer components
The `.table-stack` media block (@media max-width: 767.9px, hides thead, block-displays tr/th/td as cards, td::before renders data-label, th[scope=row] becomes the card title) is defined inside `@layer components` in resources/css/app.css. It needs NO Tailwind config — it's plain CSS. Any new responsive-table behavior must extend this utility, not add per-blade duplicates. `td` is a flex column, so `.atlas-stamp` inside a cell gets `align-self: flex-start` — without it every stamp stretches to the full card width. Ruled data tables (reports and staff registers) use the shared `.atlas-register-table` + `.atlas-register-table-wrap` block, whose `<caption>` is visually hidden but kept for semantics.

## Icons are generated Lucide inline SVG
Icons render through `<x-icon name="…" size="12|14|16|18|20" />` (`App\View\Components\Icon` + `App\Support\IconMap`) from `resources/icons.php`, which is generated by `scripts/build-icons.mjs` from `lucide-static`. Never hand-edit the generated map; run `npm run icons` after adding a name, and `npm run icons:check` (also covered by `IconTest`) proves it is in sync. Semantic renames live in `resources/icons.manifest.json` so a Lucide rename never touches views; icons resolved through a variable (timeline marks, notification types, `StampIcon`) are listed under its `always` array because the scanner cannot see through values. Status stamps use `App\Support\StampIcon::for($label)` inside the existing span, keeping the word and tone first; neutral metadata stamps stay text-only. Decorative icons are `aria-hidden` + `focusable="false"`; only a meaningful standalone icon takes `label` (renders `role="img"`). Icons are `currentColor`, 2px stroke (the bell overrides to 1.75), never animated, and never replace a text label. `.icon` sets `display:inline-block; flex:none; vertical-align:-0.125em`; size comes from width/height attributes so inline SVG still sizes on the asset-free error page.

## Shared record-sheet components
`.atlas-callout` is neutral by default and only takes the warning edge/tint under `data-state="flagged"` (both the roster attention callout and the student-progress position block use it; the label/copy slots are `.atlas-callout-label`/`-figure`/`-copy`). `.atlas-attempts` + `.atlas-attempt` are the shared `<details>` disclosure (summary = title | mono meta | figure, `+`/`−` marker). `.atlas-record-entry-facts--wide` widens a facts strip to 640px when it carries a date/time value that would otherwise wrap in the default 460px four-up grid. Keep `.atlas-record-entry-figures` as the flex wrapper when an entry head carries two stamps. `.atlas-index-filters--staff` is the 4-field staff variant (2 tracks by default, 4 at ≥1024px — the ≤899.9px single-column rule for `.atlas-index-filters` wins on equal specificity because it comes later, so no extra mobile rule is needed); apply it only when the fourth field actually renders. `.atlas-register-table--evidence` drops the 8.5rem row-label min-width and renders `tbody th` as a 12.5px mono key so report documents read as evidence rather than prose. The console-era `.atlas-teacher`/`.teacher-*` block has been deleted — do not reintroduce it (or any `teacher-*` wrapper); teacher surfaces are `.atlas-records` sheets.

## Admin record sheets reuse the shared grammar
Admin views add no new world: they compose the records sheet above plus three small blocks. `.atlas-form` is the padded column around an admin form, `.atlas-form-grid` its 2-track field grid (1 track ≤899.9px), `.atlas-form-field` a field cell (`--wide` spans both tracks), with `.atlas-field-help` / `.atlas-field-error` for the two sub-lines and `.atlas-form-actions` for the button row — field controls stay `terminal-input`, labels reuse `.atlas-lesson-entry-label`. `.atlas-row-actions` is the inline flex wrapper for row-level forms/links; `.atlas-row-action` is the small underlined text action (`.atlas-row-action--danger` is the red one) and deliberately sits outside `.btn` so registers do not fill with boxes. `.atlas-choice-list` / `.atlas-choice` / `.atlas-choice-name` are the two-track (one track ≤899.9px) checkbox membership rows. `.atlas-record-figures` is the padded wrapper for a bare `.log-facts` strip inside a record group — add any new padded group child to the ≤767.9px `padding-inline: 16px` list, or it keeps its desktop 20px inset on phones.

## Dark mode is a three-place token system
Colour tokens are `--cq-*` runtime vars: `:root` holds light values, `.dark` (on `<html>`) overrides them, and `@theme inline` maps every `--color-*`/`--font-*` token to the runtime var so utilities inline `var(--cq-*)`. `:root` also defines `--color-*` aliases — ~435 legacy `var(--color-*)` references in app.css/student.css depend on them; never delete the aliases. Adding a token = `@theme inline` entry + `:root` value + `.dark` override (+ `--color-*` alias only if it must be reachable as `var(--color-*)`). No-flash bootstrap: the inline script in layouts/app.blade.php sets `.dark` + `data-theme-mode` from localStorage `cq-theme` before first paint (anything other than `dark`, including missing storage, is light); app.js keeps `aria-pressed` on the two `[data-theme-set]` options in step with the applied mode, and the CSS draws the active option from `data-theme-mode` so it is right on the first paint. The old three-state group (Light / System / Dark, `.atlas-theme` / `data-theme-value`) must not come back: a "System" option breaks the promise that the choice stays in force until the student changes it. The body computation grid (4 repeating-linear-gradients) is the world ground on every surface — do not reintroduce `background-image: none` on body or shell.


## Sticky toolbars need `overflow-x: clip` on body
`html`/`body` use `overflow-x: hidden` in @layer base. `body { overflow-x: hidden }` makes the body a scroll container, which silently breaks `position: sticky` for in-page toolbars (the mission filter bar did not stick). `body` is now `overflow-x: clip`; keep clip unless sticky toolbars are removed. The `.atlas-index-filters` bar inside `[data-mission-list]` sticks at `top: 66px` under the 64px sticky shell. `.atlas-register-table :is(th, td).is-number` right-aligns numeric report columns at ≥768px.

## Student interaction pass (2026-10-22)
Buttons use the shared `--cq-ease-out` curve: hover is a 150ms tone shift (primary keeps its 2px offset shadow step), press is a 1px translate (primary keeps its 3px print press), and arrow icons marked `data-arrow` travel 2px on hover only under `(hover:hover) and (pointer:fine)`. All motion is CSS transform/opacity and is cancelled by the global `prefers-reduced-motion` block; no loops, glows or shadows at rest. Row feedback is a 4-6% ink tint on `.atlas-timeline-event`, `.atlas-path-mission`, `.atlas-assessment-entry`, `.atlas-record-entry` and `.atlas-register-table tbody tr`. Feature entrances are one 240ms `cq-rise-in`; progress fills use `cq-meter-in` with `transform-origin:left`; the timeline staggers only its first eight rows; the challenge run notification uses `cq-runlog-in`. Maintain the one-primary-CTA rule: do not add a second filled button beside an existing primary action.
