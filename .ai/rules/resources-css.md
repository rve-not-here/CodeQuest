# Resources Css

## Console chrome is gone; guest chrome is next
The admin console block (`.atlas-admin`, `admin-management`, `admin-*` tables/forms/toolbars, `.console-sidebar*`, `.panel-pagination`, `.admin-crumbs`/`.admin-row-link*`/`.admin-beat-*`) has been deleted from app.css — do not reintroduce it. Every authenticated surface (student, teacher, admin) is an `.atlas-records` sheet. Still standing until the guest phase: the `body.console-ui` block (guest/auth pages) and the `.guest-access-*` Mission Atlas login styles. `manual-footer` is likewise guest-only. Filter labels are not a class: `.atlas-index-filter > label` carries the eyebrow treatment (same metrics as `.atlas-lesson-entry-label`), so plain `<label>` inside a filter grid is correct.

## Structure and utilities (Engineer's Log)
Tailwind v4 CSS-first: no tailwind.config.*; the system lives in `@theme` in resources/css/app.css and the tokens are the real colour authority in both themes — never hard-code palette hexes in blades. Light and dark are one palette under two lights; dark mode is a class strategy on `<html>` with a no-flash inline script, system default and an explicit Light/Dark/System toggle. Fonts load through the laravel-vite-plugin `bunny()` helper (resources/js/app.js / app.css), never a hand-written hosted stylesheet. After editing app.css, re-run `npm run build` or the served manifest CSS won't change; run `npm run build` before declaring a visual change complete.

## .table-stack responsive utility lives in @layer components
The `.table-stack` media block (@media max-width: 767.9px, hides thead, block-displays tr/th/td as cards, td::before renders data-label, th[scope=row] becomes the card title) is defined inside `@layer components` in resources/css/app.css. It needs NO Tailwind config — it's plain CSS. Any new responsive-table behavior must extend this utility, not add per-blade duplicates. `td` is a flex column, so `.atlas-stamp` inside a cell gets `align-self: flex-start` — without it every stamp stretches to the full card width. Ruled data tables (reports and staff registers) use the shared `.atlas-register-table` + `.atlas-register-table-wrap` block, whose `<caption>` is visually hidden but kept for semantics.

## Shared record-sheet components
`.atlas-callout` is neutral by default and only takes the warning edge/tint under `data-state="flagged"` (both the roster attention callout and the student-progress position block use it; the label/copy slots are `.atlas-callout-label`/`-figure`/`-copy`). `.atlas-attempts` + `.atlas-attempt` are the shared `<details>` disclosure (summary = title | mono meta | figure, `+`/`−` marker). `.atlas-record-entry-facts--wide` widens a facts strip to 640px when it carries a date/time value that would otherwise wrap in the default 460px four-up grid. Keep `.atlas-record-entry-figures` as the flex wrapper when an entry head carries two stamps. `.atlas-index-filters--staff` is the 4-field staff variant (2 tracks by default, 4 at ≥1024px — the ≤899.9px single-column rule for `.atlas-index-filters` wins on equal specificity because it comes later, so no extra mobile rule is needed); apply it only when the fourth field actually renders. `.atlas-register-table--evidence` drops the 8.5rem row-label min-width and renders `tbody th` as a 12.5px mono key so report documents read as evidence rather than prose. The console-era `.atlas-teacher`/`.teacher-*` block has been deleted — do not reintroduce it (or any `teacher-*` wrapper); teacher surfaces are `.atlas-records` sheets.

## Admin record sheets reuse the shared grammar
Admin views add no new world: they compose the records sheet above plus three small blocks. `.atlas-form` is the padded column around an admin form, `.atlas-form-grid` its 2-track field grid (1 track ≤899.9px), `.atlas-form-field` a field cell (`--wide` spans both tracks), with `.atlas-field-help` / `.atlas-field-error` for the two sub-lines and `.atlas-form-actions` for the button row — field controls stay `terminal-input`, labels reuse `.atlas-lesson-entry-label`. `.atlas-row-actions` is the inline flex wrapper for row-level forms/links; `.atlas-row-action` is the small underlined text action (`.atlas-row-action--danger` is the red one) and deliberately sits outside `.btn` so registers do not fill with boxes. `.atlas-choice-list` / `.atlas-choice` / `.atlas-choice-name` are the two-track (one track ≤899.9px) checkbox membership rows. `.atlas-record-figures` is the padded wrapper for a bare `.log-facts` strip inside a record group — add any new padded group child to the ≤767.9px `padding-inline: 16px` list, or it keeps its desktop 20px inset on phones.

## Dark mode is a three-place token system
Colour tokens are `--cq-*` runtime vars: `:root` holds light values, `.dark` (on `<html>`) overrides them, and `@theme inline` maps every `--color-*`/`--font-*` token to the runtime var so utilities inline `var(--cq-*)`. `:root` also defines `--color-*` aliases — ~435 legacy `var(--color-*)` references in app.css/student.css depend on them; never delete the aliases. Adding a token = `@theme inline` entry + `:root` value + `.dark` override (+ `--color-*` alias only if it must be reachable as `var(--color-*)`). No-flash bootstrap: the inline script in layouts/app.blade.php sets `.dark` + `data-theme-mode` from localStorage `cq-theme` before first paint; app.js syncs the `[data-theme-value]` buttons' aria-pressed. The body computation grid (4 repeating-linear-gradients) is the world ground on every surface — do not reintroduce `background-image: none` on body or shell.
