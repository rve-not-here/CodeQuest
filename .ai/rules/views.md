## Responsive grids need an explicit mobile column count
Any grid with a responsive breakpoint (e.g. `grid gap-4 md:grid-cols-2`) MUST declare `grid-cols-1` (or another explicit mobile template). With `grid-template-columns` unset, implicit tracks size to the item's max-content, and nowrap/truncate labels (activity beats, roster cells) blow the panel out to ~700px+ on 360–430px viewports — no `overflow` anywhere shows it because the track itself grows. Guard: check every `class="grid` in the view. US-610: students/dashboard/mission all had this latent bug.

## Responsive tables use .table-stack + data-label per cell
Data tables that must adapt at <768px use `class="table-stack atlas-register-table"` on the <table> and a `data-label` attribute on every cell (the label shown above the value in the stacked-card layout; `td::before { content: attr(data-label) }`). The row label is a `<th scope="row" data-label="…">` — `.table-stack` block-displays `th` too, so it becomes the card title. Applied to the /students roster, the /student-progress register tables, and report tables. Keep the <thead> in the DOM (semantics) — the CSS hides it. Internal `overflow-x-auto` scrolling on a table is NOT an acceptable substitute under §50.0.

## Icons + theme control
Use `<x-icon>` for iconography — never hand-write an SVG or a glyph character (no `☀`, `⌄`, `≡`, `×`). Names resolve through the generated Lucide map; add the name in a view (or `'icon' => '…'` in a PHP map) and run `npm run icons`. Names chosen at runtime (timeline marks, notification types, `App\Support\StampIcon`) must also be listed in `resources/icons.manifest.json` under `always` — `IconTest` proves the generated map covers them. Status stamps render the word first and may take a 12px icon via `StampIcon`; roles, counts, course codes and other metadata stay plain. Keep the text label beside the icon; icon-only controls (theme, notifications, menu) carry an `aria-label`. The colour theme is one `<x-theme-toggle />` button cycling light → dark (there is no system option; absent storage means light); both icons render and CSS reveals the current one from `html[data-theme-mode]`, so there is no icon flash and no `aria-pressed` state. ## Grid columns never take their width from min-content
A grid item's automatic minimum size is its min-content, and a line of markup in a <pre> never wraps — so an auto-sized track grows to the longest line and the column runs under the next column. The lesson brief therefore sets an explicit `grid-template-columns: minmax(0, 1fr)` and zeroes the minimum on its items (`.atlas-lesson-brief > * { min-width: 0 }`); the reference output then scrolls inside its own listing instead of widening the page. When you add a grid container that can hold code or a long token, give it minmax(0, 1fr) and min-width: 0 on the items, and check it in the browser at 1440 and 390 (the page must not scroll sideways). The lesson's reference output is the canonical `.log-listing` (the same component the challenge page shows) with `tabindex="0"` and aria-label 'Reference output', set flush inside the specimen: one frame, one ink, one shadow — never a second near-duplicate of a listing style.
