# Views

## Editor/preview reuse + small-viewport verification trap
Reuse window.CodeQuest.CodeMirror via the cq:codemirror-ready event; preview iframes are sandboxed (allow-scripts only), srcdoc, no server call on RUN (ADR-0002). Headless chromium clamps --window-size to 500px min, so verify 360/390/430 via same-origin iframes sized exactly. @vite emits absolute URLs from app.url, so static-page verification must run on that host. Never let a probe div carry unbroken JSON tokens — they lay out ~557px and fabricate phantom page overflow.

## Completion banner keys off currentCourse null, not mission exhaustion
The dashboard "Course complete / Awaiting new directives" banner must render only when the derived current course is null (i.e. every active course has had its Boss Challenge passed — DashboardService::currentCourse skips hasPassed). Do NOT add `|| $nextMission === null` back: finishing all missions of a course yields a null next mission while the Boss Challenge is still outstanding, so that old condition told students they had "cleared every active course" prematurely. Caught and fixed by AssessmentIntegrationTest (US-414).

## Responsive grids need an explicit mobile column count
Any grid with a responsive breakpoint (e.g. `grid gap-4 md:grid-cols-2`) MUST declare `grid-cols-1` (or another explicit mobile template). With `grid-template-columns` unset, implicit tracks size to the item's max-content, and nowrap/truncate labels (activity beats, roster cells) blow the panel out to ~700px+ on 360–430px viewports — no `overflow` anywhere shows it because the track itself grows. Guard: check every `class="grid` in the view. US-610: students/dashboard/mission all had this latent bug.

## Responsive tables use .table-stack + data-label per cell
Data tables that must adapt at <768px use `class="table-stack atlas-register-table"` on the <table> and a `data-label` attribute on every cell (the label shown above the value in the stacked-card layout; `td::before { content: attr(data-label) }`). The row label is a `<th scope="row" data-label="…">` — `.table-stack` block-displays `th` too, so it becomes the card title. Applied to the /students roster, the /student-progress register tables, and report tables. Keep the <thead> in the DOM (semantics) — the CSS hides it. Internal `overflow-x-auto` scrolling on a table is NOT an acceptable substitute under §50.0.

## Admin console is a records sheet too (admin phase, A1–A6)
Every admin view renders inside the atlas shell (`body.atlas-ui.admin-ui`) — there is no console chrome left. The recurring shape is the records sheet described above: running head `Records · <page> · Platform scope` with the page's back/forward links or a scope stamp, eyebrow + h1 + lede, an optional `.log-facts` fact strip, then `.atlas-record-group` sections. Admin-specific grammar:

- Registers list rows as `th[scope=row]` (link to the record) + `data-label` on every cell, status/role/audience as `.atlas-stamp` tones (`--grn` active/published, `--amb` locked/draft, `--acc` admin/deleted/archive, `--vio` students, `--ink` neutral), and row actions as `.atlas-row-action` (+ `--danger`), wrapped in `.atlas-row-actions`.
- Forms use `.atlas-form` (padded column), `.atlas-form-grid` (2 tracks, 1 below 900px), `.atlas-form-field` (+ `--wide` for full-width), `.atlas-field-help` / `.atlas-field-error`, `.atlas-form-actions`, and `terminal-input` controls — the same field markup as the public filters. Multi-group editors put one form per group (`base fields`, then one membership group per form) so each save stays atomic.
- Long option sets (classroom membership) use `<fieldset class="atlas-choice-list">` with `.atlas-choice` rows (checkbox + username + mono real name); `.atlas-record-figures` is the padded wrapper for a bare `.log-facts` strip inside a group.
- `data-metric="<name>"` on a `<dd>`/`<td>` whose text starts with digits is a test binding (`AdminDashboardTest`, `AdminAnalyticsTest`, `AdminSystemTest`); keep them when rewriting markup.
- Empty states are `.atlas-records-empty` (title + copy + action), never a bare status message. Page-level notices stay inline panels: success `border-success/40 bg-success-soft`, failure `border-danger/40 bg-danger-soft`, rejected query `border-warning/40 bg-warning-soft`.
- Copy is sentence case everywhere (`New user`, `Boss Challenge`, `Page 1 of 2`); caps come from `.atlas-lesson-entry-label` / `.atlas-stamp` / `.atlas-row-action` CSS.
